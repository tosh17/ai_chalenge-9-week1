# День 33. Ассистент поддержки s1

Это новый сервис, не продолжение кулинарного чата. Он смотрит домашний сервер s1 (`10.10.1.101`): модель выбирает инструмент MCP, а сервер сам выполняет узкую команду. Произвольный shell модели не отдаётся.

Поддержка отвечает на вопрос о сервисе. Она читает тикет и пользователя из JSON-CRM, хвост логов контейнера и FAQ. В ответе два раздела: причина и рекомендация.

## Пример

Тикет `TCK-210` Анны: не открывается GitLab. Ассистент должен посмотреть контейнер `gitlab`, а не решить, что аккаунт заблокирован.

```bash
set -a && source .env && set +a
export S1_HOST=troot@10.10.1.101
go run ./cmd/ops support -q "TCK-210 Почему не открывается GitLab?"
```

Страница: `go run ./cmd/ops`, затем http://127.0.0.1:8095/

Кнопка «Что запущено» вызывает `list_services` и показывает контейнеры s1.

## Откуда данные

- CRM: `support/crm/users.json`, `support/crm/tickets.json`
- FAQ: `docs/faq.md`
- Логи: MCP `service_logs` → `sudo -n docker logs` на s1

На s1 пользователю `troot` нужен `NOPASSWD` только на `/usr/bin/docker`, иначе список контейнеров не снять.
