# День 31. Ассистент разработчика

Чат по-прежнему на http://127.0.0.1:8080/. Кулинарный агент дней 20–30 остаётся. Новая команда `/help` отвечает на вопросы о самом репозитории: читает документацию через RAG и живое состояние git через MCP.

## Задание

- Документация проекта в RAG: `README.md` и `docs/`.
- MCP к репозиторию: текущая ветка, дерево файлов, diff.
- `/help` отвечает по этим источникам, а не по памяти диалога.

## Что сделано

Индекс строится из `README.md` и всех `docs/**/*.md`. Эмбеддинги считает Ollama на домашнем сервере: `http://10.10.1.101:11434`, модель `nomic-embed-text` (768 измерений). Векторы кэшируются в `data/rag/index.json`. Если Ollama недоступна, поиск остаётся лексическим по тем же чанкам.

MCP-сервер `project` (`go run ./cmd/mcp project` или `bin/mcp project`) отдаёт три инструмента:

| Инструмент | Что возвращает |
| --- | --- |
| `git_branch` | имя ветки, короткий HEAD, число грязных путей |
| `list_files` | дерево каталогов, по умолчанию глубина 2 |
| `git_diff` | `status`, `--stat` и при необходимости патч |

`/help` на каждый вопрос вызывает все три инструмента, подмешивает 5 ближайших фрагментов документации и просит выбранную в чате модель ответить только по этому контексту. Голый `/help` задаёт вопрос о структуре проекта.

Примеры:

```
/help как устроен проект
/help какие есть HTTP API
/help где лежат схемы памяти
/help какая сейчас ветка
/help покажи git diff
```

Под ответом чат показывает ветку, источники и имена вызванных MCP-инструментов. Если модель не ответила, в пузырь попадают сами фрагменты и вывод git.

## Запуск

```bash
cp .env.example .env
set -a && source .env && set +a
go build -o bin/mcp ./cmd/mcp
go run ./cmd/server
```

Переменные RAG: `RAG_OLLAMA_URL`, `RAG_EMBED_MODEL`, `RAG_TOP_K`, `RAG_CACHE_PATH`. Полный список — в [docs/config.md](docs/config.md).
