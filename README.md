# Day 12 · Персонализация ассистента

Поверх трёхслойной памяти (день 11) агент держит **явный профиль пользователя**:
кто это, какой стиль ответа, какой формат и какие ограничения.
Активный профиль подмешивается **в каждый запрос** отдельным system-блоком.

## Профиль

Файл: `data/memory/profiles.json`. Переключение не трогает STM/WM/LTM.

| Поле | Зачем |
| --- | --- |
| имя, роль | к кому обращаться и в каком контексте |
| стиль | кратко / формально / просто |
| формат | списки, вывод-сначала, абзацы с примерами |
| ограничения | без воды, без эмодзи, лимит пунктов |

Пресеты из коробки:

- **Бригадир · кратко** (`brief`)
- **Заказчик · формально** (`exec`)
- **Новичок · с примерами** (`learner`)

Промпт:

```
system: роль + правила слоёв
system: === ПРОФИЛЬ ПОЛЬЗОВАТЕЛЯ ===   (если inject_profile)
system: === ДОЛГОВРЕМЕННАЯ ===
system: === РАБОЧАЯ ===
STM… + текущая реплика
```

Сними галку «Профиль» — персонализация останется в файле, но модель её не увидит.

Из чата: `#стиль …`, `#формат …`, `#ограничение …`, «предпочитаю кратко / списком», «формально», «без воды».

## Проверка

Кнопка **Демо профилей**: один и тот же вопрос («две бригады на объекте»)
для трёх пресетов и без профиля. В отчёте видно, что стиль меняется сам.

## Быстрый старт

```bash
cp .env.example .env
export $(grep -v '^#' .env | xargs)
go run ./cmd/server
```

Откройте: **http://localhost:8080**

## API

### `POST /api/chat`

`{ "message", "provider?", "inject_stm?", "inject_wm?", "inject_ltm?", "inject_profile?" }`

### `GET /api/profile` · `POST /api/profile` · `POST /api/profile/activate`

Список, сохранение, переключение `{ "id": "exec" }`.

### `POST /api/profile/demo`

Сравнение ответов на одном probe.

Слои памяти: `GET /api/memory`, как в дне 11.

## Структура

```
internal/memory/profile.go  — книга профилей + FormatProfileBlock
internal/agent/             — inject в каждый Handle, демо сравнения
internal/handler/web        — селектор профиля в меню
```
