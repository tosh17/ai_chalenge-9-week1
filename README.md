# Day 13 · Состояние задачи как конечный автомат

Поверх слоёв памяти задача — это **автомат**, а не свободный статус:

`planning → execution → validation → done`

На каждом этапе хранятся **текущий шаг** и **ожидаемое действие**.
Пауза — отдельный флаг: её можно поставить на любом этапе, не сбрасывая шаг.

## Состояние

| Поле | Зачем |
| --- | --- |
| этап | где мы в процессе |
| шаг | что делается прямо сейчас |
| ожидаемое действие | кто должен сделать следующий ход |
| пауза | стоп без смены этапа |
| уже сделано | не пересказывать при «продолжи» |

Файл тот же: `data/memory/working.json` (поле `task`).

## Пауза и продолжение

- **Пауза** на любом этапе: агент коротко подтверждает и ждёт, работу не продолжает.
- **Продолжить**: тот же этап и шаг, без «итак, напомню план».
- Из чата: `#пауза`, `#продолжи`, `#дальше`, `#этап execution`, `#шаг …`, `#ожидаю …`.

## Проверка

1. **Пример задачи** — посев на `execution`, шаг «стены 1 этажа», уже сделаны план и фундамент.
2. **Пауза** → спросите «напомни весь план с начала».
3. **Продолжить** → «продолжай»: должен взять стены/материал, а не пересказывать фундамент.

Кнопка **Демо паузы** гоняет оба хода подряд и пишет отчёт.

## Быстрый старт

```bash
cp .env.example .env
export $(grep -v '^#' .env | xargs)
go run ./cmd/server
```

Откройте: **http://localhost:8080**

## API

### `POST /api/task/event`

`{ "event": "pause|resume|advance|set|finish", "stage?", "step?", "expect?" }`

### `POST /api/task/seed`

Пример задачи на `execution`.

### `POST /api/task/demo`

Пауза, затем продолжение на одном и том же посеве.

Чат: `{ "message", "provider?", "inject_stm?", "inject_wm?", "inject_ltm?", "inject_profile?" }`

## Структура

```
internal/memory/task.go     — автомат, переходы, FormatTaskBlock
internal/agent/             — inject в каждый Handle, префиксы, демо
internal/handler/web        — этап / шаг / пауза / продолжить
```
