# День 32. Автоматическое ревью кода

Пайплайн на GitLab s1 смотрит новый merge request: забирает diff и список файлов, подмешивает RAG по документации и коду и возвращает ревью.

Чат дня 31 по-прежнему на http://127.0.0.1:8080/, команда `/help` не изменилась. Ревью — отдельная команда `cmd/review` и джоба CI.

## Задание

Ассистент на PR:

- получает diff и изменённые файлы
- использует RAG: документация и код
- выдаёт текст ревью: потенциальные баги, архитектурные проблемы, рекомендации

## Что сделано

GitLab на s1: http://10.10.1.101:8929, SSH `ssh://git@10.10.1.101:2224`. Раннер `local` уже зарегистрирован (docker, сеть `lab`).

`.gitlab-ci.yml` запускает `ai-review` на событии merge request:

```bash
go run ./cmd/review -out review.md
```

Ответ пишется в лог джобы, в артефакт `review.md` и, если API пускает job token, комментарием к MR.

Индекс ревью шире, чем у `/help`: `README.md`, `docs/**/*.md` и `*.go`. Эмбеддинги считает Ollama `nomic-embed-text` на `http://10.10.1.101:11434`. Текст ревью пишет DeepSeek, ключ берётся из `DEEPSEEK_API_KEY` в переменных CI, не из git. Без ключа три раздела всё равно собираются по diff и найденным фрагментам.

Подробности — в [docs/review.md](docs/review.md).

## Запуск локально

```bash
set -a && source .env && set +a
go run ./cmd/review -base day31 -head HEAD -out review.md
```

## Как включить на s1

1. В GitLab создать проект и запушить ветку `day32`.
2. В CI/CD variables добавить masked `DEEPSEEK_API_KEY`.
3. Открыть merge request. Джоба `ai-review` стартует сама.

Пример комментария:

```
## Потенциальные баги
...

## Архитектурные проблемы
...

## Рекомендации
...
```
