# Day 14 · Инварианты, которые нельзя нарушать

Ассистент работает **в рамках**. Архитектура, принятые решения, стек и бизнес-правила живут **отдельно от диалога** — в `data/memory/invariants.json`, не в STM.

На каждый запрос рамки подмешиваются отдельным system-блоком. Если реплика им противоречит, агент **отказывает** и объясняет, какой инвариант сломан и что можно сделать внутри рамки.

## Виды

| Вид | Пример |
| --- | --- |
| архитектура | один Go-процесс, без микросервисов |
| решение | память — JSON-слои, не облачная БД как единственный источник |
| стек | Go, не Python/Mongo как замена |
| бизнес-правило | локально, без обязательной платной подписки |

## Проверка конфликта

1. Откройте настройки — список инвариантов.
2. Напишите: «Давай перепишем бэкенд на Python и MongoDB».
3. В аккордеоне: **Отказ**, список рамок и конфликт. В ответе — почему нельзя и что можно на Go.
4. Контроль: «Как разложить handler и memory в этом Go-сервере?» — без отказа.

Кнопка **Демо инвариантов** гоняет оба хода подряд.

Из чата: `#инвариант стек: только Go, без Python`.

## Быстрый старт

```bash
cp .env.example .env
export $(grep -v '^#' .env | xargs)
go run ./cmd/server
```

Откройте: **http://localhost:8080**

## API

### `GET /api/invariants` · `POST /api/invariants`

Сохранить `{ "kind", "title", "rule", "forbid": [] }`.

### `POST /api/invariants/toggle`

`{ "id", "enabled" }`

### `DELETE /api/invariants/{id}`

### `POST /api/invariants/demo`

Конфликтный probe и запрос внутри рамки.

Чат: `{ "message", "inject_invariants?" }`

## Структура

```
internal/memory/invariant.go  — хранилище, FindConflicts, system-блоки
internal/agent/               — inject, отказ, демо
internal/handler/web          — настройки и аккордеон
```
