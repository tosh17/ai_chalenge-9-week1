# День 20. Orchestration MCP

## Задание

Зарегистрировать несколько MCP-серверов.

Агент должен:

- выбирать нужный инструмент
- корректно маршрутизировать запросы
- выполнять длинный флоу взаимодействия

Проверить сценарий, в котором используются инструменты с разных серверов, и правильность выбора и порядка вызовов.

## Что сделано

Чат кулинарный. Четыре отдельных MCP, агент сам выбирает сервер.

| Сервер | Где лежит | Инструменты |
| --- | --- | --- |
| поиск | `bin/mcp search`, код в `internal/mcpsrv/search.go` и `image.go` | `web_search`, `web_fetch`, `web_image` |
| перевод | `bin/mcp translate`, код в `internal/mcpsrv/translate.go` | `translate_en_ru` |
| погода | Kotlin, `mcp/open_meteo` | `get_weather`, `observe_city` |
| схема | `bin/mcp diagram`, код в `internal/mcpsrv/diagram.go` | `draw_flow` |

Длинный флоу на рецепте проходит несколько серверов по порядку:

1. `web_search` — только английские страницы
2. `web_fetch` — открывает одну такую ссылку
3. `translate_en_ru` — переводит выдержку на русский
4. `web_image` — фото блюда
5. `draw_flow` — блок-схема реальных вызовов, её рисует система по следу, не модель

Ответ пользователю только по-русски. Фото стоит в тексте рядом с блюдом, схема — в конце. Сырой путь `/media/...` в сообщении не показывается.

Погода остаётся отдельным сервером и вызывается, только если спросили про погоду.

Подключение всех процессов — `cmd/server/main.go`, функция `attachMCP`.
